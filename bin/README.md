# bin — pi-scoped shims

`infisical` delegates to `security/infisical-shim.ts`, supplies the machine token, checks the selected project before starting the CLI and refuses interactive commands. A refused project prints its name and the one-time human step. An unknown project ID prints a broken-link message. Authentication and project-link rules live in `skills/infisical/SKILL.md`. Claude Code must call this shim by its explicit path.

Pi prepends this dir first in PATH for the tools it spawns. Keep only what must
shadow a system binary or is pi-owned:

- `open` — thin delegate to the machine-wide rule in `~/.config/shims/open`
  (`dot_config/shims/open`): `.zshenv` prepends that dir, so every zsh session
  resolves `open` there; pi tool sessions hit this delegate first. Keeping the
  delegate makes tool coverage independent of how pi's parent shell assembled
  PATH.
- `tailnet-link` — symlink to the command of `skills/tailnet-links/scripts/`, so a
  pi tool session finds it on a machine where `tailnet-link setup` has not
  linked it into `~/.local/bin` yet.
- `syneva` — generated by the syneva pi extension; do not hand-edit.
- `fd`, `rg` — arm64 binaries shadowing/baking in brew versions for pi sessions.
- `pi-drift.ts` — `pnpm run drift`: fails when the running `pi` differs from
  `AUDITED_PI_VERSION` (`extensions/lib/ui/pi-runtime.ts`).
- `pi-token-pull` — on every machine that did not sign in to Codex (the
  Pots desktops, the workspace VMs), copies the Codex access
  token the signed-in machine publishes in the vault into `auth.json`. Needs
  `INFISICAL_UNIVERSAL_AUTH_CLIENT_ID`/`_SECRET` in its environment and the
  vault binding `~/.config/agent-secrets/core-vault.json`.
- `chezmoi-reconcile` — on the Mac Studio, drops from the chezmoi source every
  managed target deleted live; a no-op elsewhere. Run at session start and stop
  by `extensions/commands/chezmoi-reconcile/` and by the Claude Code hooks in
  `~/.claude/settings.json`.
- `magpie-claude-token-sync` — on the machine hosting the Magpie gateway,
  reads `CLAUDE_CODE_OAUTH_TOKEN` from the vault location the binding names,
  registers it in Magpie through a temporary local `magpie web`, proves the
  account answers a request held to that account alone (a 5-minute gateway
  key, removed afterwards), then forgets every other `Claude setup-token`
  account. A failed proof leaves the older accounts in place, and Claude
  Code's own sign-in is never touched. Prints the account, the HTTP status and
  the removed names. The token stays in the child's environment and a loopback
  request body. Needs the machine identity in its environment, like
  `pi-token-pull`.
- `magpie-gateway-priority` — on the machine hosting the Magpie gateway,
  `check` fails when its launchd job is not `Interactive` and `fix` sets the
  type and reloads the job, restoring the file when the gateway does not
  answer afterwards; a no-op elsewhere. `check` runs at session start by
  `extensions/model/gateway-priority/`.

- `test-pace.ts` — Claude Code calls the shared test decision with its current transcript: `node --experimental-transform-types ~/.pi/agent/bin/test-pace.ts --session <JSONL> --intent <bug or requirement> <test paths...>`. It reads the human's requests, questionnaire answers and relays itself and prints `pace` (`bug`, `logic`, `none`) and `permission` (`new`, `existing`, `none`: the human consent covering every named path). It sends no source code and does not mint Pi grants.
- `eval-test-pace.ts` — run through the core vault providers environment to calibrate the pinned pace, consent, operation and stop-target questions, against the cases `test-pace-cases.ts` loads; a consent case may carry the agent `question` its reply answers, and a stop-target case the `thread` a stop may cancel grants in. Expectations are agent-labelled. Each report separates false grants, unavailable calls and conservative refusals; any false grant, a missed withdrawal or stop included, or unavailable call fails the run.

Personal cross-context tools live in `~/.local/bin` (last in PATH on purpose),
not here.
